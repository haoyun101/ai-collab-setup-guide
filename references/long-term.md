# references · 长期

> 触发：搭建四件事做完之后；换窗口、加支线、交下游、要改治理文档时。
> 主文件 `SKILL.md`，本文件只装 §13.1、§14、§16、§17。

---

## §13.1 治理层的收敛条件

**四件事做完即为够用**：文件框架建立 / 角色明确 / 版本控制就绪 / 执行角色的常驻规范落地（没有执行角色的项目此条免）。

**此后治理文档的任何修改都必须搭车，不得单独开一轮。**

> 判据：**这一轮如果不改治理文档，用户的正事推进会被卡住吗？** 不会 → 攒着，下次跟正事一起做。
> **硬计数：连续两轮的产出都是治理文档而不是项目实质内容，停下来问用户一句「要不要先把正事推一步」。**

**新建文档前先问四句**，任一为"是"就别新建：工作区里有没有同层同职责的文件（有 → 沿用）？这条内容换个项目还成立吗（成立 → 只能进通用层）？有没有现成正文能承载（有 → 加一节，不建文件）？它是不是每轮都读、但从没影响过决定？

## §14 支线、窗口、下游

**支线交付包**：标识（名称提案 + 来源定位 + 归属提案）/ 确认凭证 / 真值清单（每个数值给「来源标识 + 实际值」，读不到标 ⚠️ 不推导）/ 构成与复用 / 多版草案全带并标哪版为准 / 裁决点清单 / 未完成清单。

**按任务分窗，不按省事分窗：一个窗口只干一条线上的事。** 内容一杂，模型就开始记串、答偏。

判据是**这件事跟窗口里已有的内容是不是同一条线**：

- **同一条线 → 沿用**。它已授权、已有上下文，省一次冷启动
- **切到另一条线 → 换窗**。哪怕上下文还很空，也换
- 另外两个该换的信号：上下文塞满回答变差 / 单个批次做完该退役

**换窗成本本来就该很低**——冷启动包由文件生成，不用重发材料。觉得换窗麻烦到需要将就，说明冷启动包没做好，去修那个。

**开新窗口给冷启动包**：背景 + 当前版本状态 + 待办（含可执行的精确内容）+ 要上传的文件清单。可由"项目过程文档当前版本 + 待办摘要"直接生成。

**交给下游产出端**：主交付物 = 真源文件本身，不是文字转述。转述只作"差异说明 + 归属 + 位置"。产出走对账，不并入事实源，不一致时默认事实源对。

## §16 用户的协作偏好

**他自带就直接用**，不另起一份、不重新提炼。你的职责变成：按它规定的格式给增量提案；发现它没覆盖的情形主动提；**不反向篡改他已确认条目的语义**。

**中途才拿出来的也一样，立刻切换**，你这轮之前写的通用层作废。顺序：只读快照他的原文（一个字不改）→ 设为该层唯一入口 → 你新建的重复件按 §5 阶段 2⑥ 出推荐、删不删他拍 → 项目层只留项目特例、通用规则改成章节指向 → 更新所有冷启动入口和引用 → 验一遍他的原文没被动过。

**没有自带就从对话里提炼，不要发问卷。** 观察：确认颗粒度 / 沟通密度 / 决策风格 / 交付形态 / 成本敏感度。每条标明是**推测**还是**他说过的**，推测的请他改；用他自己的说法；宁可少写几条——写了不执行的偏好比没写更糟。

他第二次表达同一个不满，当轮就补进这一层。

## §17 持续演进

**17.1 加与砍**

该加：同一个错误犯第二次；用户第二次提同一个不满；某条线的活多到一个窗口跑不完。
该砍：某条规则每轮都读但从没影响过决定；为"更规范"加的模板/字段填写成本大于收益；某个角色连续几轮无事可做。

**17.2 两条关于改规则的规则**

**① 新写进规范的条款，同一轮内立刻自查自己有没有违反。** 规则写完之后，模板、话术这类现成物料要回头对一遍。

**② 同一个错误犯到第二次，不要再调参数，要换形态。** 阈值型规则依赖预估，预估会错；硬条件型不依赖判断，才拦得住。

**17.3 归属**：换个项目还成立吗？成立 → 协作偏好层；不成立 → 项目过程层；是执行纪律 → 执行纪律层。**别新建文件装规则。**

**17.4 文档变大**：把"入口 + 索引"和"内容"分开，开窗只读入口。

**17.5 同一个摩擦出现第二次** → 回到 17.2。其余"什么时候读哪一份"见 `SKILL.md` 的「本包怎么读」与「动手前必查」。
